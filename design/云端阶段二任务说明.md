> 给云端会话的一句话：**「读 design/云端阶段二任务说明.md，照里面的要求做完阶段二。」**

## 背景

《零压拆船厂 ZERO PRESSURE》，Godot 4.7 GDScript 的 2D 太空拆船游戏。阶段一（1.2–1.9：性能、存档、船型数据化与验证器、训练 TS-1、三档提示、剧情、学徒考核、设置与文本校对）已全部完成并在 main 上。阶段二是合同循环：灰鹭号可以反复拆，越拆越强。玩法结构全部由用户在 design/DECISIONS.md 里定案。

用户特别在意台词不要被 AI 改写或代写：故事性文字必须留给用户写（见硬性规则 1）。

代码风格：注释用英文、简洁；中英文 UI 文本都放在 scripts/txt.gd 的 S 表里（[中文, 英文]）。

## 硬性规则（用户定的，必须遵守）

1. **文案分工**：梁工台词、终端播报、船载记录、报废原因、陷阱名称和复盘说明、里程碑演出等故事性文字一律不准自己写，全部用 data/copy.json 的编号占位（编号以 design/阶段二文案_提示词.md 为准；新增占位要补进提示词的待写清单）。只有按钮、栏目名、数值说明这类功能性界面文字可以自己写。
2. 不要派子代理，所有工作自己做。
3. 测试绝不能读写真实存档和设置：Game.testing 判定、SaveGame.path / train_path、Career.path、Txt.cfg_path 都要在测试里指向测试文件。
4. 阶段二只有灰鹭级。变体只改危险配置、货物、事故破损、图纸偏差，不改船体结构；同型号零件和接口编号必须稳定（2.8 工程笔记依赖它）。新船型要先出设计稿给用户审阅。
5. 每完成一项：在 design/ROADMAP.md 对应条目打勾并写上验收证据，同步 design/TODO.md，提交并推送。
6. 回归：每项完成后至少跑
   - tests/full_run.gd（回收率 99.9%、净 $110,910 不能变）
   - tests/full_run.gd -- careless（14.2% / $8,005）
   - tests/validate_ship.gd -- all
   - tests/save_fuzz.gd
   - tests/text_fit.gd

   变体会改变数值的话，固定种子下的手工灰鹭号 GR-001 结果必须保持不变。新增中文后要跑 python tools/subset_font.py（需要 fontTools；字体源 NotoSansSC-VF.ttf 不在仓库里，云端拿不到就在汇报里列出新增的字，交给本地重新生成）。
7. **提交只署用户本人**：提交说明和 PR 里不加 `Co-Authored-By: Claude`，不写 "Generated with Claude Code" 之类的署名或尾注，也不在提交说明里提 Claude。即使你的默认设置要求加归属行，也以这条为准。推送前用 `git log --format=%B | grep -i co-authored` 确认没有。

## 运行环境

- 仓库里的 tools/run_test.sh 写死了 Windows 路径。云端要自己装 Linux 版 Godot 4.7（4.7-stable，从 godotengine 官方 GitHub releases 下载 Linux x86_64 版），用 `godot --headless --path . -s tests/xxx.gd -- 参数` 跑。
- 先跑一次 `godot --headless --path . --import` 生成类缓存；新增 class_name 后都要再跑。
- 需要截图和窗口的测试在云端跑不了，在汇报里列出哪些画面需要回本地验证。
